3. SOAR — infra's up, automation isn't built

TheHive and Cortex are both running and linked to each other — that part's genuinely done. What's missing for 3.1 through 3.3 is a custom Cortex analyzer, which means writing an actual Python class against Cortex's analyzer SDK (cortexutils). That's real, scoped development work, not something to fake with a placeholder script. 3.4 (ticket creation) is arguably done by definition — a TheHive case already is the ticket, there's no separate system to bolt on.

Next concrete step: build one analyzer against something I already have live data for — take a username observable, query LocalStack's IAM for what that account can actually do. That's a real target, not a hypothetical one, since LocalStack's already running.
